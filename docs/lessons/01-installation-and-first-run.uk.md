# Урок 1. Встановлення і перший запуск

!!! abstract "Мета уроку"
    Встановити агента, підключити мовну модель і поставити перше питання.

![Бородатий малюк-будівельник](../assets/images/baby-builder-bearded.webp)

Всі ми колись були маленькими та навчались усьому з самого початку.
У дорослому житті кожен з нас має свій багаж знань, здобутий у школі, університеті та протягом професійної діяльності. Він допомагає нам розвиватись і здобувати нові знання.

Якщо раптом цей урок здасться вам занадто складним — згадайте немовлят: вони вивчають усе з нуля і ще навіть не вміють користуватись штучним інтелектом.

Спочатку уявімо себе звичайними користувачами (не програмістами), але вже досить просунутими, щоб власноруч встановити будь-яку Python-програму.

## 1.1 Встановлення tooled як звичайної програми через `pipx`

tooled — це скорочена назва tooled-ai-agent. Відкрийте термінал (bash чи PowerShell) на своїй машині: неважливо, чи це Ubuntu, macOS або Windows, команда встановлення працює всюди однаково:

```bash
pipx install git+https://github.com/PetroShevchenko/tooled-ai-agent.git
```

Якщо не спрацювало, це значить лише те, що на вашій машині не встановлено потрібні пакети. Перевірте, чи встановлено Python та git:

```bash
python --version
git --version
```

!!! note
    tooled потребує **Python 3.11 або новішого**. У Linux і macOS команда може називатися `python3`.

Встановлення необхідних пакетів залежить від операційної системи.

### Windows

Якщо Python та git ще не встановлено, встановіть їх у PowerShell:

```powershell
winget install --id Python.Python.3.12 --exact
winget install --id Git.Git --exact
```

Закрийте та знову відкрийте PowerShell, щоб встановити pipx:

```powershell
py -3.12 -m pip install --user pipx
py -3.12 -m pipx ensurepath
```

Знову відкрийте новий термінал PowerShell і повторіть команду встановлення tooled — тепер усе має вийти як слід.

### Ubuntu

Встановіть одразу всі необхідні залежності за допомогою менеджера пакетів:

```bash
sudo apt update
sudo apt install git python3 pipx -y
pipx ensurepath
```

!!! note
    В Ubuntu 22.04 Python 3.10 — замало для tooled. Оновіть систему або [встановіть новіший Python](https://launchpad.net/~deadsnakes/+archive/ubuntu/ppa).

Відкрийте новий термінал і повторіть спробу встановити tooled:

```bash
pipx install git+https://github.com/PetroShevchenko/tooled-ai-agent.git
```

### macOS

Якщо команда `brew` ще недоступна, спочатку встановіть [Homebrew](https://brew.sh) і виконайте вказівки інсталятора, щоб додати brew до PATH.

Далі відкрийте термінал і встановіть усі необхідні залежності за допомогою менеджера пакетів brew:

```bash
brew install git pipx
pipx ensurepath
```

Відкрийте новий термінал і знову повторіть спробу встановити tooled:

```bash
pipx install git+https://github.com/PetroShevchenko/tooled-ai-agent.git
```

### Перший запуск

Тепер спробуйте запустити агента, просто набравши в терміналі `tooled`.
Можете навіть написати агенту «Привіт», на що той декілька секунд подумає, що вам відповісти, і врешті видасть Python-traceback з повідомленням про помилку, оскільки ви ще не підключили жодної моделі, з якою агент може взаємодіяти. Як це зробити — у розділі [1.3](#13).

## 1.2 Встановлення tooled для розробки

У попередньому розділі ми встановили tooled як готову програму. pipx поклав її код в окреме віртуальне середовище, де його не зручно ні читати, ні змінювати. Щоб працювати з вихідним кодом, потрібно встановити tooled спеціально для розробки.

Цей крок можна поки що пропустити й одразу перейти до [підключення моделі](#13). Але до нього доведеться повернутись, щойно вас зацікавить вихідний код агента.

Встановлення залежить від вашої операційної системи.

### Linux / macOS

Відкрийте bash-термінал і клонуйте репозиторій tooled-ai-agent у свою домашню директорію або в інше місце на диску. Далі перейдіть у клонований репозиторій і запустіть скрипт `install.sh` — він встановить усе необхідне для подальшої роботи. Наприкінці встановлення скрипт підкаже, що далі потрібно активувати віртуальне середовище, — тож активуйте його.

```bash
git clone https://github.com/PetroShevchenko/tooled-ai-agent.git
cd tooled-ai-agent
./install.sh                 # creates .venv and installs the package with dev and docs extras
source ./env.sh activate     # activates .venv
```

Після активації віртуального середовища вже можна запускати tooled:

```bash
tooled
```

### Windows

Для встановлення tooled-ai-agent у Windows є два варіанти:

- встановити віртуальне середовище WSL2 та запускати bash-термінал Ubuntu прямо у вашій Windows-системі (рекомендований спосіб);
- встановити tooled-ai-agent нативно у Windows через PowerShell і використовувати PowerShell для подальшої роботи.

!!! note "Чому рекомендовано WSL2"
    tooled-ai-agent розробляється мною в Ubuntu Linux, тому для Windows його потрібно тестувати окремо. Якщо ви оберете другий спосіб встановлення, то саме ви і будете тією людиною, яка протестує tooled-ai-agent у Windows.

### Windows: WSL2

Відкрийте термінал PowerShell і виконайте команду:

```powershell
wsl --install -d ubuntu
```

Після встановлення bash-термінал Ubuntu має з'явитися прямо в запущеному PowerShell, тобто ви відразу можете перейти до встановлення tooled-ai-agent у [Linux / macOS](#linux-macos). Якщо Windows попросить дозвіл на зміни або перезавантаження — погодьтеся, після перезавантаження встановлення продовжиться.

Однак наступного разу bash-термінал Ubuntu доведеться відкривати окремо: натисніть клавішу Win, знайдіть через пошук Ubuntu і виконайте:

```bash
cd ~/tooled-ai-agent
source ./env.sh activate
tooled
```

За потреби кількість ядер процесора, обсяг пам'яті та інші ресурси, виділені для WSL2, можна змінити: натисніть клавішу Win і знайдіть через пошук WSL Settings.

!!! important
    У BIOS Setup вашого комп'ютера має бути увімкнено віртуалізацію, інакше при спробі запустити Ubuntu ви отримаєте повідомлення про помилку:
    `0x80370114 The operation could not be started because a required feature is not installed.`

### Windows без WSL

Перевірте, чи встановлено на вашому комп'ютері git та Python:

```powershell
python --version
git --version
```

Якщо ще ні — встановіть їх, дотримуючись інструкцій з розділу [Windows](#windows) вище.

Тепер відкрийте PowerShell і клонуйте репозиторій tooled-ai-agent:

```powershell
cd $HOME\Documents
git clone https://github.com/PetroShevchenko/tooled-ai-agent.git
cd tooled-ai-agent
```

З директорії tooled-ai-agent виконайте встановлення:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -e ".[dev,docs]"
$env:LITELLM_LOCAL_MODEL_COST_MAP = "True"   # use the bundled model cost map, no network fetch
tooled
```

!!! note
    Якщо PowerShell не дає виконати `.venv\Scripts\activate` через політику виконання скриптів, дозвольте локальні скрипти для свого користувача і повторіть активацію:
    `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

Змінна `LITELLM_LOCAL_MODEL_COST_MAP` діє лише в поточному сеансі PowerShell. Наступного разу перейдіть у директорію tooled-ai-agent, знову активуйте середовище й задайте змінну перед запуском `tooled`.

### Код першого уроку

Клонований репозиторій містить найновішу версію агента з гілки `main`. Код кожного уроку зафіксовано git-тегом `lesson-NN`. Щоб код у вас збігався з цим уроком, перейдіть на тег `lesson-01` (команди однакові для bash і PowerShell):

```bash
git checkout lesson-01    # код уроку 1
git checkout main         # повернутися до найновішої версії
```

Пакет встановлено в режимі редагування (`pip install -e`), тому перевстановлювати його після перемикання не потрібно — `tooled` одразу запускає код обраного уроку.

!!! warning
    `git checkout lesson-01` переводить репозиторій у стан detached HEAD. Як при цьому не втратити свої зміни — див. [Як користуватися кодом уроків](../index.uk.md#lesson-code).

## 1.3 Підключення моделі

Тепер настав час обрати та підключити модель штучного інтелекту. tooled-ai-agent взаємодіє з моделями через [LiteLLM](https://docs.litellm.ai/docs/providers) — бібліотеку, яка підтримує десятки постачальників, зокрема такі:

| Постачальник | Вартість | Встановлення | Приклад `model` |
|---|---|---|---|
| [Ollama](https://ollama.com) | безкоштовна, локальна | `ollama pull qwen3:1.7b` | `ollama_chat/qwen3:1.7b` |
| [Gemini API](https://aistudio.google.com) | безкоштовний тариф із добовими лімітами | ключ у `GEMINI_API_KEY` | `gemini/gemini-3.8-flash` |
| [Vertex AI](https://cloud.google.com/vertex-ai) | платна (застосовуються кредити Google Cloud) | `gcloud auth application-default login` + project ID в `extra` | `vertex_ai/gemini-3.8-flash` |
| [OpenAI](https://openai.com) | платна | ключ у `OPENAI_API_KEY` | `openai/gpt-5-mini` |
| [Anthropic](https://www.anthropic.com/) | платна | ключ у `ANTHROPIC_API_KEY` | `anthropic/claude-sonnet-5-5` |
| [DeepSeek](https://www.deepseek.com/en/) | платна, низька вартість | ключ у `DEEPSEEK_API_KEY` | `deepseek/deepseek-chat` |

### Конфігураційний файл config.toml

Ваш AI-агент поки що нічого не знає про модель, яку ви збираєтесь використовувати. Щоб вказати модель за замовчуванням, а також мати змогу перемикатися на інші моделі, потрібно записати інформацію про моделі в конфігураційний файл config.toml.

Конфігураційний файл створюється автоматично під час **першого запуску** `tooled` — агент виводить при цьому рядок `Created default config:` із шляхом до файлу. Шлях залежить від операційної системи:

- Linux: `~/.config/tooled-ai-agent/config.toml`
- macOS: `~/Library/Application Support/tooled-ai-agent/config.toml`
- Windows: `%LOCALAPPDATA%\tooled-ai-agent\config.toml`

config.toml копіюється з шаблону default_config.toml, який однаковий на всіх пристроях. Усі ваші подальші налаштування зберігаються саме у вашому config.toml.

!!! note
    Перевстановлення tooled-ai-agent не змінює ваш config.toml — налаштування зберігаються. Але й нові параметри з оновленого шаблону default_config.toml у наявний файл самі не потраплять. Якщо видалити config.toml, при наступному запуску агент створить його знову з шаблону.

Кожна модель описується в config.toml окремим **профілем** — секцією `[models.<назва>]`:

```toml
[models.local]
model = "ollama_chat/qwen3"
temperature = 0.2
```

Профіль, який агент використовує за замовчуванням, вказується в секції `[llm]` рядком `default = "<назва>"`:

```toml
[llm]
default = "local"
```

Профілі для всіх трьох варіантів нижче вже є в шаблоні — потрібно лише змінити кілька наявних рядків.

!!! warning
    Не дописуйте секції в кінець файлу: секцію в TOML не можна оголосити двічі, і агент не запуститься з помилкою
    `tomllib.TOMLDecodeError: Cannot declare ('llm',) twice`. Знаходьте потрібні секції у файлі й змінюйте наявні рядки.

Оберіть один із трьох варіантів підключення моделі. Для першого запуску достатньо будь-якого з них, а інші можна налаштувати пізніше.

### Локальна модель: ollama_chat/qwen3:1.7b

Це безкоштовна модель, яку ви встановлюєте на свій комп'ютер, і вона використовує апаратні ресурси вашої машини. Тобто якщо продуктивність машини невисока, то й модель працюватиме повільно. Перевага такої моделі — можливість спробувати агента без реєстрації та отримання API-ключів. Почнімо саме з неї.

Спочатку завантажте та встановіть програму [Ollama](https://ollama.com/download).

Відкрийте термінал (bash чи PowerShell) і завантажте модель командою (час завантаження залежить від швидкості інтернету):

```bash
ollama pull qwen3:1.7b
```

!!! note
    Модель 1.7b — найлегша з родини qwen3, і для перших уроків її достатньо. Для складніших багатокрокових задач у наступних уроках може знадобитися більша модель, наприклад `qwen3:8b`, якщо дозволяє пам'ять.

Сервер Ollama має працювати, поки ви користуєтеся агентом. У Windows і macOS його запускає програма Ollama, у Linux — системна служба або команда `ollama serve`.

Тепер відкрийте config.toml у будь-якому текстовому редакторі, знайдіть секції `[llm]` і `[models.local]` і змініть наявні рядки, щоб агент використовував модель Ollama за замовчуванням:

```toml
[llm]
default = "local"                    # profile used by plain `tooled`

[models.local]
model = "ollama_chat/qwen3:1.7b"     # LiteLLM format: provider/model
temperature = 0.2                    # optional
```

!!! success "Готово"
    Локальну модель підключено — переходьте до [пункту 1.4](#14) і спробуйте агента.

### Хмарна модель з API-ключем: gemini/gemini-3.8-flash

Хмарна модель працює на серверах Google, тому швидкість не залежить від потужності вашого комп'ютера, а якість відповідей значно вища, ніж у маленької локальної моделі.

Найпростіший спосіб спробувати хмарну модель — Gemini API з API-ключем. Для `gemini-3.8-flash` є безкоштовний тариф з обмеженою кількістю запитів, і його вистачає для уроків курсу.

1. Відкрийте [Google AI Studio](https://aistudio.google.com/apikey), увійдіть в обліковий запис Google і створіть API-ключ ([офіційна інструкція](https://ai.google.dev/gemini-api/docs/api-key)).
2. Переконайтеся, що біля ключа вказано тариф **Free**.

!!! warning "Ключ безкоштовний, лише якщо проєкт без оплати"
    Кожен API-ключ належить проєкту Google Cloud і отримує його тариф. Якщо до проєкту прив'язано платіжний акаунт (наприклад, ви вже користуєтеся в ньому Vertex AI), ключ працюватиме за платним тарифом. Для безкоштовного використання створіть ключ в окремому проєкті, до якого оплату не прив'язано.

3. Збережіть ключ у змінній середовища `GEMINI_API_KEY`. **Не записуйте ключ у config.toml** — агент читає його лише зі змінної середовища.

Linux / macOS / WSL:

```bash
export GEMINI_API_KEY="ваш-ключ"
```

Windows (PowerShell):

```powershell
$env:GEMINI_API_KEY="ваш-ключ"
```

Змінна діє лише в поточному терміналі: запускайте `tooled` у тому самому вікні. Щоб не задавати її щоразу, у Linux і WSL допишіть рядок з `export` у файл `~/.bashrc`, у macOS — у `~/.zshrc`, а у Windows виконайте `setx GEMINI_API_KEY "ваш-ключ"` і відкрийте новий термінал.

Профіль `[models.gemini]` для цієї моделі в config.toml вже є, змінювати його не потрібно. Залишилося зробити його профілем за замовчуванням — знайдіть секцію `[llm]` і змініть рядок `default`:

```toml
[llm]
default = "gemini"

[models.gemini]
model = "gemini/gemini-3.8-flash"
temperature = 0.2
```

!!! success "Готово"
    Gemini API підключено — переходьте до [пункту 1.4](#14) і спробуйте агента.

### Хмарна модель через Vertex AI: vertex_ai/gemini-3.8-flash

Через Vertex AI працює та сама модель `gemini-3.8-flash`, тому якість відповідей буде такою самою, як у безкоштовному Gemini API. Різниця в умовах використання:

| | Gemini API, безкоштовний тариф | Vertex AI |
|---|---|---|
| Вартість | безкоштовно | оплата за токени (можна використати кредити Google Cloud) |
| Ліміти запитів | невеликі: при частих запитах доведеться чекати | значно вищі |
| Ваші дані | Google може використовувати запити й відповіді для покращення своїх продуктів, їх можуть переглядати люди ([умови Gemini API](https://ai.google.dev/gemini-api/terms)) | не використовуються для навчання моделей |
| Інші можливості | лише моделі Gemini API | вибір регіону, інші моделі з Model Garden, інструменти Google Cloud |

Для уроків курсу вистачить безкоштовного тарифу. Vertex AI варто обрати, якщо ліміти заважають працювати або ви надсилаєте моделі робочий код і дані, які не можна віддавати Google для покращення продуктів.

Для Vertex AI потрібен обліковий запис Google Cloud із прив'язаною оплатою.

Перед налаштуванням агента підготуйте Google Cloud:

1. Створіть проєкт Google Cloud, увімкніть для нього оплату та Vertex AI API — покроково це описано в [офіційній документації Vertex AI](https://cloud.google.com/vertex-ai/docs/start/cloud-environment). Запам'ятайте **ID проєкту** (project ID), наприклад `gen-lang-client-XXXXXXXXXX` — він показаний у [списку проєктів](https://console.cloud.google.com/cloud-resource-manager) консолі Google Cloud.
2. Встановіть [Google Cloud CLI](https://cloud.google.com/sdk/docs/install) (команда `gcloud`).
3. Увійдіть у свій обліковий запис, щоб агент міг звертатися до Vertex AI від вашого імені ([докладніше про ADC](https://cloud.google.com/docs/authentication/set-up-adc-local-dev-environment)):

```bash
gcloud auth application-default login
```

API-ключ для Vertex AI не потрібен: LiteLLM сам знаходить облікові дані, збережені командою `gcloud`.

У config.toml профіль для цієї моделі вже є — **знайдіть секцію `[models.flash]`** і замініть `your-project-id` на ID свого проєкту:

```toml
[models.flash]
model = "vertex_ai/gemini-3.8-flash"
extra = { vertex_project = "gen-lang-client-XXXXXXXXXX", vertex_location = "global", drop_params = true }
```

Параметри в `extra` агент передає в LiteLLM без змін:

- `vertex_project` — ID вашого проєкту Google Cloud;
- `vertex_location` — регіон, у якому виконується запит; `global` дозволяє Google самому обрати доступний регіон;
- `drop_params = true` — LiteLLM мовчки відкидає параметри, які модель не підтримує, замість того щоб повертати помилку.

Інші параметри описано в [документації LiteLLM для Vertex AI](https://docs.litellm.ai/docs/providers/vertex).

Залишилося зробити цей профіль профілем за замовчуванням — у секції `[llm]` має стояти `default = "flash"` (у шаблоні це значення вже вказано).

!!! success "Готово"
    Vertex AI підключено — переходьте до [пункту 1.4](#14) і спробуйте агента.

## 1.4 Перший запит

Перевірте, що агент бачить ваш профіль моделі:

```bash
tooled --list
```

Навпроти профілю, який ви налаштували (`local`, `gemini` або `flash`), має стояти позначка `(by default)`. Тепер запустіть агента й напишіть йому «Привіт»:

```bash
tooled
```

Цього разу замість помилки ви маєте отримати відповідь від моделі. Порожній рядок завершує роботу агента.

Щоб спробувати інший налаштований профіль, не змінюючи `default`, вкажіть його під час запуску, наприклад `tooled -m gemini`.

## 1.5 Команди чату

Крім звичайних питань, в агента можна вводити команди — вони починаються з `/` і не надсилаються моделі.

| Команда | Що робить |
|---|---|
| `/help` | показує список команд |
| `/models` | показує профілі моделей з config.toml; позначки `(by default)` і `(current)` вказують на модель за замовчуванням і поточну |
| `/model <назва>` | перемикає на інший профіль, наприклад `/model local`; історія розмови зберігається |
| `/reset` | очищує історію поточної розмови — модель «забуває» попередні питання |
| `/usage` | показує, скільки токенів витрачено за сесію: `↑` — надіслано моделі, `↓` — отримано |
| `/history` | показує 10 останніх збережених розмов і шляхи до їхніх файлів |
| `/search <слова>` | шукає питання, які містять **усі** вказані слова, в усіх збережених розмовах |

### Клавіші

| Клавіші | Що роблять |
|---|---|
| порожній рядок (`Enter`) | завершує роботу агента |
| `Ctrl+D` | завершує роботу агента |
| `Ctrl+C` під час введення | стирає набраний рядок; натиснуте вдруге протягом 2 секунд — завершує роботу |
| `Ctrl+C` під час відповіді | скасовує запит до моделі, агент чекає на нове питання |

### Параметри запуску

Модель і конфігураційний файл можна вибрати ще до запуску чату:

| Параметр | Що робить |
|---|---|
| `tooled` | запускає чат із моделлю за замовчуванням (`[llm] default`) |
| `tooled -m <назва>`, `--model <назва>` | запускає чат із вказаним профілем, наприклад `tooled -m local` |
| `tooled --list` | показує профілі моделей і завершує роботу |
| `tooled -c <файл>`, `--config <файл>` | використовує інший конфігураційний файл замість config.toml |
| `tooled -h`, `--help` | показує довідку про параметри |

Профіль також можна задати змінною середовища `AGENT_MODEL`, наприклад:

`bash`
```bash
AGENT_MODEL=local tooled
```

`PowerShell`
```powershell
$env:AGENT_MODEL="local"; tooled
```

Порядок пріоритету: `-m` → `AGENT_MODEL` → `[llm] default`.

Команда `tooled-ai-agent` — повна назва, яка працює так само, як `tooled`.

### Де зберігаються розмови

Кожна розмова автоматично зберігається у двох файлах: `.md` — для читання людиною, `.jsonl` — повні дані для програм. Файли створюються лише після першого питання, тож порожні сесії архів не засмічують. При завершенні агент виводить рядок `Saved:` зі шляхом до `.md`-файлу.

Архів лежить у підпапках `sessions/РРРР/ММ/`:

- Linux: `~/.local/share/tooled-ai-agent/sessions/`
- macOS: `~/Library/Application Support/tooled-ai-agent/sessions/`
- Windows: `%LOCALAPPDATA%\tooled-ai-agent\sessions\`

Ім'я файлу складається з дати, часу й першого питання, наприклад `2026-11-24_031305_pryvit.md`. Розташування архіву можна змінити змінною середовища `TOOLED_AI_AGENT_HOME`.

`/search` виводить дату, знайдене питання і шлях до файлу з номером рядка — відкрийте цей файл у будь-якому редакторі, щоб перечитати всю розмову.

## Якщо щось пішло не так

- **`pipx: command not found`** або **`tooled: command not found`** — закрийте й знову відкрийте термінал після `pipx ensurepath`.
- **pipx повідомляє про невідповідну версію Python** — tooled потребує Python 3.11 або новішого (див. примітку для Ubuntu 22.04).
- **`Connection refused` при зверненні до моделі Ollama** — сервер Ollama не запущено.
- **`TOMLDecodeError`** — у config.toml синтаксична помилка або секцію оголошено двічі; рядок і стовпчик помилки вказано в повідомленні.
- **`API key not valid`** від Gemini API — ключ скопійовано з помилкою, або змінну `GEMINI_API_KEY` задано в іншому терміналі.
- **`429`** / **`RESOURCE_EXHAUSTED`** від Gemini API — вичерпано ліміт безкоштовного тарифу; зачекайте або перевірте ліміти в AI Studio.
- **`DefaultCredentialsError`** при зверненні до Vertex AI — не виконано `gcloud auth application-default login`.
- **`PERMISSION_DENIED`** або **`403`** від Vertex AI — у `vertex_project` вказано неправильний ID проєкту, або для проєкту не ввімкнено оплату чи Vertex AI API.
